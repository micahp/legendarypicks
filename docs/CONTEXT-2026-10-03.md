## ESPN 403s: the shared cache existed and never hit (fixed, host config)

Dev and prod live scoreboard timers both set `LP_ESPN_CACHE_DIR=backend/.espn-cache`, and a live
scoreboard is cached 20 s (`LIVE_TTL`). Dev fired at `:10`, prod at `:40`: every read found the
other's copy 30 s old, so the cache never hit and ESPN saw two requests per league per minute.
At 16:50 CDT MLB and NCAAF were refused on every run on both.

Prod's live timer now fires at **`:20`** (`/etc/systemd/system/legendarypicks-scoreboards-live-prod.timer`,
comment in the file; the old value was `:40`; unit files are not in git). Each environment still
runs its own code and writes its own DB, so dev/prod drift is untouched; only ESPN's raw response
is shared, keyed by URL. First run after the change: dev spent 2 requests, 0 failed; prod spent
**0 requests**, 0 failed. Micah's concern about consolidating the timers into one is why it was
done this way.

If refusals continue at half the volume, the next step is moving live scores off ESPN (Kalshi
live data for football, statsapi, the NHL API, nba.com, fotmob).
