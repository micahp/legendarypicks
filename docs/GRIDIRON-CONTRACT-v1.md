# GRIDIRON-CONTRACT v1: Legendary Picks <-> Gridiron Physics

Status: proposed interface, version 1.0. **This document must remain byte-identical in both repositories.** Scope: **simulate an upcoming NFL game before kickoff and replay its generated plays in 3D**. Not a historical-game picker or a live "What If" product.

LP owns the game state, conditional play/outcome probabilities, participants/outcome sampling, legality, full game chronology and statistical result. Gridiron owns physics/rating enrichment, route/formation reconstruction, renderer, simulation playback and UI. LP need not import `engine/play.js`; Gridiron need not import LP's model internals.

## Exchange surfaces

**Input**: pregame snapshot (scheduled matchup, as-of, projected available roster/roles, strength/pace priors, rules) generated by LP.

**Output from LP**: a **complete, immutable, hypothetical full-game play script**, scores and stats. LP emits *sampled football events and outcomes*, not motion frames. A training source game or an actual observed event must never be relabeled as a prospective simulation.

**Output from Gridiron**: play-by-play rendered playback plus optional replay metadata (cameras, per-play frame timestamps, reconstructed lineup confidence), without modifying the LP event result.

**Optional reverse future interface**: Gridiron can export as-of physical ratings/attributes (SPD, ACC, AGI, STR, PMV, FMV, BSH, MCV, ZCV, PRS, PUR etc.) as experimental context for the LP model. They are estimates, not verified tracking data. V1 rendering needs this on the Gridiron side, not LP training.

## IDs and data provenance

- `game_id`: stable LP/nflverse-compatible scheduled game key, e.g. `2026_07_DEN_SEA` (**example only; not asserted to be a real fixture**).
- `simulation_id`: immutable identifier derived from game/snapshot/model/seed; avoid collisions between changed models or snapshots.
- `play_id`: unique synthetic ID `<simulation_id>:<sequence>`; Gridiron's existing `rng(S.id)` can use it without an engine PRNG change.
- `player_id`: canonical GSIS ID where available. Gridiron maintains a checked GSIS <-> ESPN ID crosswalk; if unmapped, resolve by reviewed roster ID or fail explicitly, **never join by ambiguous name**.
- `as_of`: UTC timestamp **earlier than kickoff** and as-of data manifest hash. A snapshot can be replayed later but must remain frozen; explicitly report absent/inferred roster or availability.
- `model_version`, `rules_version`, `schema_version`, RNG seed, source/artifact hashes and provenance labels are mandatory.

## Canonical state

A play's `state_before` and `state_after` must include:
- `quarter` (1–4, or OT index under the versioned rules)
- `clock_seconds` remaining in that **period** (not nflverse's whole-game field)
- `offense_team` (team with the ball), `defense_team`
- `home_score`, `away_score`
- `down` (1–4 on normal scrimmage plays, nullable for kickoff/PAT)
- `yards_to_go` (nullable for administrative/special situations)
- `yardline_100`: **yards from the offense's spot to the opponent's goal** (offense-relative), 0..100 for ordinary ball spots
- `home_timeouts`, `away_timeouts`, `drive_index`.

`down`, `yards_to_go`, and `yardline_100` mean the state *before* the action, and after is derived by the rules reducer from that action's sampled outcome. A score does not teleport, and results must reconcile to summary stats.

## Event vocabulary and translation

Model event families: `run`, `pass_complete`, `pass_incomplete`, `interception`, `sack`, `qb_scramble`, `punt`, `field_goal`, `extra_point`, `two_point_try`, `kickoff`, `kneel`, `spike`, `fumble`, `penalty`, `safety`, `period_end`, `game_end`. Each family has a schema-defined required set of participants, signed gain, event-specific result fields and nullability; unknown kinds fail instead of being shown as a benign run.

Gridiron adapter should map event outcomes onto its existing `S.kind` names (e.g. `pass_complete` -> `complete`, `pass_incomplete` -> `incomplete`, `interception` -> `int`, `field_goal` -> `fg`) and `lineup`, `units`, `qb`, `target`, `carrier`, `air`, `yac`, `gain`, `td`, `dir`, `los`. Unsupported/complex rules events may receive a clear schematic/title-card visualization initially, **never a falsely specific physical replay**.

Physics conversion: LP's offense-relative `yardline_100` is **not** Gridiron's absolute field-x `los`. For attack direction `dir=+1`, `los=100-yardline_100`; for `dir=-1`, `los=yardline_100`. Choose the direction from the versioned field/end-zone mapping for that simulated period; preserve `yardline_100` in the LP record.

The generated player, team and score outcomes are authoritative **for that hypothetical simulation**. Reconstructed defender routes, aim points, lineup assignments or collisions must not be described as observed or model-predicted if they were authored heuristics. Existing Gridiron physics is outcome-constrained reconstruction and may visually deviate from its generated end spot; report that discrepancy rather than silently editing LP's results.

## Ratings payload (Gridiron-owned)

Gridiron publishes a versioned `ratings_snapshot` for eligible players with GSIS ID and physics-native ID, team, estimated skill attributes, `mass`, `vmax`, `tau`, `alat`, `drive`, `reach`, confidence/imputation and effective as-of date. Rating outputs used for pregame scenes **must not** use performance from after the target game's kickoff. If a historical player cannot be represented, explicitly warn/fail rather than silently using an unrelated modern player.

LP's statistical generator does not need Gridiron to compute the play outcome. A future physically causal simulation profile can use the reverse attributes with separately evaluated evidence, without changing the v1 play-result interface.

## Execution / discovery (proposed)

- `GET /api/gridiron/v1/upcoming-games`: fixtures with stable game/team IDs and UTC kickoff.
- `POST /api/gridiron/v1/simulations`: `{game_id, as_of_utc, seed, mode:"pregame_full_game"}` -> versioned simulation response or async job reference.
- `GET /api/gridiron/v1/simulations/{simulation_id}`: immutable full play log, summary, provenance, optional cache metadata.

Offline development can generate identical JSON through an LP CLI and Gridiron can load a local fixture with no deployed API. Do not expose placeholder endpoints as working until wired. Caching is by `(game_id, snapshot_hash, model_version, rules_version, seed)`.

## Compatibility and validation gates

- Shared v1 contract docs and JSON fixtures are synchronized across repos; CI checks byte equality when practical.
- LP records validate as complete football games: legally ordered possessions/downs, clocks and scores; play stats equal sums from the play log.
- Same snapshot/version/seed -> identical LP outcome log. Same generated play ID and Gridiron physics version -> identical physics replay, subject to separately documented rendering nondeterminism.
- LP generates two **distinct upcoming matchups**, each with nonempty legitimate pregame rosters, and Gridiron loads and renders both.
- The renderer runs selected plays from a full game with timeline, scoreboard, drives, camera and player selection. Do not require real-time execution of thousands of 120 Hz full-game trials.
- Distinct seeds result in varied plausible situations and final scores. Variability is not evidence of forecast accuracy.
- Original ESPN Film Room is untouched and continues to run. The earlier Slant What If prototype can remain independent.
- Source labeling must visibly distinguish **HYPOTHETICAL MODEL SIMULATION** from **HISTORICAL RECONSTRUCTION**, and preserve model/seed information.
- Missing inputs, unsupported plays and replay failures must surface explicitly. No fabricated scores, silent substitution of a completed game's lineup, or claim that outcomes were physics-predicted.

## Excluded from v1

Historical game catalog/browser, branching a live or historical game, user play calling, exact broadcast replay, licensed route/coverage charting, physics-determined statistical outcomes, sportsbook advantage, and highly validated market forecast probabilities. Those are later initiatives, **not dependencies for watching a generated NFL game ahead of kickoff**.

## Implementation order

1. Freeze and test JSON fixture + game/state rules contract.
2. LP produces a complete seed-reproducible hypothetical game.
3. Gridiron adapts it into existing per-play `simulatePlay()` scripts using pregame roster/rating estimates.
4. Gridiron provides an **upcoming-game picker**, **Simulate Game** action and full playable timeline, not a historical game picker.
5. Evaluate coherence, coverage, replay visuals and pregame reproducibility. Defer all "What If From Here" scope.
