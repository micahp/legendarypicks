### Legendary Picks – Context Summary (2026-06-04)
Snapshot of today's session: a ground-up rewrite of the Python sports backend, plus why it now
shares a data contract with a separate prediction-market trading project.

### Architectural Goal (≈100–200 words)
The backend was audited and found to not actually collect data: two FastAPI apps both bound port
8000 (`sports_service.py` on the unmaintained `sportsipy` HTML scraper; `nba_service.py` NBA-only on
`nba_api`), with no persistence and a hardcoded one-game-per-league fixture as the fallback path. The
goal of this rewrite is a single, reliable, multi-league data service on a free source we already
trust — ESPN's public site API — that (a) returns real games for NBA/WNBA/NHL/MLB/NFL, (b) persists
predictions and grades them against real finals, and (c) exposes a **team-strength / quality prior**
(win%, point/run differential, streak, last-10). That quality endpoint is the bridge to a sibling
prediction-market trading effort, whose research this week showed its only unfalsified edge is
*selection of genuinely undervalued quality* — exactly what `/api/{league}/strength` provides. One
provider, one normalization layer, one service; no scraping libraries at runtime.

### Audit findings that drove the rewrite
- **No real collection:** request-time passthrough → 1-game fixture fallback; no DB; in-memory predictions lost on restart.
- **Dead foundation:** `sportsipy==0.6.0` scrapes sports-reference.com, unmaintained, breaks on site changes; `nba_api` is NBA-only.
- **Correctness bugs:** fantasy score read magic positional indices (`stats[24]`…) into an nba_api rowSet; `vars(p)` dump with `lstrip("_")`; flaky live `ScoreBoard()` used despite known rate limits.
- **Hygiene:** `emulator.key` / `emulator-account.pkey` committed at repo root (flagged, not modified).

### How to run (use a venv)
```
cd backend
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/uvicorn sports_service:app --host 0.0.0.0 --port 8000
# GET /api/nba/games          GET /api/mlb/strength
# GET /api/nhl/strength/CAR    POST /api/predictions {league,game_id,predicted_winner}
```
(This sandbox's Python 3.8 lacks `ensurepip`, so the venv was pip-bootstrapped via get-pip; a normal
machine just runs the two lines above.)

### Verified
Strength covers NBA/WNBA/NHL/MLB/NFL (30/15/32/30/32 teams); games() returns live + final scoreboards;
a prediction on a finished game graded correctly against the real winner; SQLite persisted predictions
and strength snapshots.

### Frontend wiring (same session, after the backend)
The backend rewrite changed response shapes, so the frontend was audited and re-pointed. Strategy:
keep the components' stable internal `Game`/`Prediction` shapes and translate the new backend in the
**service layer (anti-corruption layer)** — components unchanged.
| File | Change |
|---|---|
| backend/espn_client.py | + `roster(league, team)` (ESPN team roster) |
| backend/sports_service.py | + `GET /api/{league}/team/{team}/roster` |
| services/sports.ts | `getGames` maps `{game_id,state,home/away.abbrev}` → internal `Game`; `submitPrediction` sends snake_case `{game_id,predicted_winner}`; `getPredictions` reads `{predictions,…}`; + `getStrength()`; dropped dead `getPlayerStats` |
| services/nbaGames.ts | `getTodaysGames` → `/nba/games` (mapped); `getTeamRoster` → `/nba/team/{id}/roster` (mapped); reuses `normalizeGame` |
| pages/api/nba/games.ts | `fastapi`/`nba_api` provider path: `/games/by-date` → `/nba/games?date=`, normalized to internal shape |

Live consumers verified covered: `pages/predict.tsx` (getGames/submit/getPredictions), `pages/scores.tsx`
(getGamesByDate via Next route), `components/GameBrowser.tsx` + `ContestCreator.tsx` (getTodaysGames/roster).
Contract validated against the running backend: games/date/roster/strength shapes + a snake_case prediction
round-trip graded correctly (predicted PHI on a PHI win → correct, accuracy reported). No `tsc` run (fresh
clone has no node_modules); types reviewed by hand.
