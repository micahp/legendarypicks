# WTA test of M2: verdict is ATP-only under the registered test

**Verdict:** M2 on 2000 history is validated on ATP and is **not** validated on WTA. The registered WTA interval,
M2 minus M1 = −0.00032 [−0.00079, +0.00016], contains zero. The declared per-tour K sensitivity does not rescue it. The
recommendation is per-tour model selection: M2 for ATP, M1 for WTA.

- **Status:** Development evidence (CP2 only). No promotion, no production change, no gate change, no lock-surface edit.
- **Data status:** 2015 to 2026 is inspected development data. 2023 to 2026 has been used for choices, and no part of it
  is a holdout.
- **Branch:** `feat/tennis-track-b-2026-10-18`. Brief: `BRIEF-TENNIS-WTA-M2-2026-10-19.md`.
- **Protocol:** [`PROTOCOL-wta-m2.md`](../research/tennis/rolling/2026-10-19/PROTOCOL-wta-m2.md), committed (`2dd7f433`)
  before the sensitivity run.

## 1. Was M2 trained on pooled ATP and WTA data?

No. The evidence is in the repository, not in a claim.

- **Ratings are per tour.** `rolling_origin.py` `winner_records(db, tour, cols)` and the live `project_day(con, tour, ...)`
  both build fresh Elo state for one tour and read only `tennis_{tour}_matches`.
- **The constants were not fitted.** K = 32 and start 1500 are the standard Elo values fixed in
  `docs/TENNIS-MATCH-BACKTEST-PROTOCOL-2026-10-14.md` (Elo baseline, line 55) before any run. The 50/50 logit weight is
  the live design. Neither was selected on either tour.
- **The pooled constants belong to a different model.** `FORM_PLAYER_HALF_LIFE` and `FORM_K` in
  `backend/tennis_match_backtest.py` were "chosen on the 2022 validation window ... for both tours". They belong to the
  point model, which M2 does not use.

So the WTA-only fit the brief asks for is the registered run already in `a1_per_tour.json`. Re-running it on WTA alone is
the same test. The null is not a pooling artefact.

## 3. Bootstrap noise at the verdict

The verdict is decided by an interval endpoint, so the endpoints were re-drawn with four extra block labels, using the
same statistic and the same 1,000 resamples (`wta_m2_mc_spread.py`, [`wta_m2_mc_spread.json`](../research/tennis/rolling/2026-10-19/wta_m2_mc_spread.json)).
The registered label reproduces the A1 record exactly.

- **WTA registered, upper 95% bound across five labels:** +0.000151 to +0.000189. It stays above zero for every label, so
  "contains zero" does not depend on the seed.
- **WTA sensitivity, upper bound across five labels:** −0.000005 to +0.000029. It straddles zero, so the sensitivity is
  not distinguishable from zero in either direction.
- **ATP registered, upper bound across five labels:** −0.001639 to −0.001601. It stays below zero for every label.

Note that the 2020 to 2026 K = 32 rows in the sensitivity table use their own block label, so they differ from the A1 window
rows in the fourth decimal of the endpoints. That is bootstrap noise, which the spread above measures.

| Possible artefact | Test | Result |

On ATP the K sensitivity changes little. M1 prefers K 24, and M2 keeps K 32. The ATP margin is −0.00196 [−0.00264, −0.00129]
in the sensitivity, against −0.00218 registered.

## 5. What this does not establish

- **The blend weight was not varied.** The protocol declared K only. The 50/50 logit weight is a live design choice, and a
  WTA-specific weight is untested. A weight sweep would need its own declared protocol.
- **There is no clean holdout.** 2023 to 2026 has been inspected, so a per-tour K that wins on WTA could only be tested
  properly on data that has not been seen. Such data does not exist yet.
- **The K sensitivity is diagnostic.** Even if it had cleared zero, it would not validate the registered M2. It would be a
  candidate for a new registered version, with its own protocol and a window that has not been inspected.

## 6. What I did not do

- No lock row was changed. No database was written. Nothing was merged to `dev`, deployed, restarted, or changed in serving.
- No constant was refitted to improve a score, and no protocol rule was changed after results were seen.
- The protocol was committed before the sensitivity ran. The one code change, a `k` argument on the replay, has a default
  equal to the registered value. The K = 32 replay was checked against the A1 record in the same run.
- No pooled number was used for the verdict. Pooled numbers are in the A1 record only.

## 7. Recommendation

Per-tour model selection: M2 on 2000 history for ATP, and M1 for WTA. The WTA result is a null under the registered test, and
the declared sensitivity leaves it on the zero boundary. A WTA-specific M2 needs a new registered version, a declared weight
and K, and a window that has not been used.

The decision to adopt per-tour selection in production belongs to Micah. Nothing has been changed here.
