## Parity gaps to close

1. **NFL accuracy:** display the already returned per-model mean Brier and its valid sample count; make the no-score state explicit. Keep NHL’s tooltip and lower-is-better explanation as the reference.
2. **Tennis accuracy:** expose a settled winner Brier for the selected winner model and show the matched graded sample count. Do not imply that the alternate markets have validated probability scores.
3. **Frozen lines:** NFL should label its stored lock-time line and show its snapshot timestamp/source. Tennis must preserve the quote present at lock for new locks; historical locks with no quote metadata remain explicitly unavailable. Preview quotes must remain labelled current, not frozen.
4. **Missed lock windows:** include scheduled games whose start passed without a model lock in the relevant record/projection view, while keeping unlocked future previews separate. Unknown start times remain unknown.
5. **Tests:** add NFL assertions for Brier/sample count, frozen-line metadata and missed locks; create a Tennis tab suite for loading/error/empty, projection-vs-settled, Brier, frozen/current/absent lines, and missed locks. Add endpoint tests for new response fields. Preserve NHL behavior and its existing tests.

The lock/forecast APIs remain league-specific; this work adds the missing read-only fields and view states without changing forecast parameters, forecasts, locked picks or official results. The Tennis model route currently creates its lock table and may write a forecast lock during a GET request (`misc.py:363-368,508-547`); that pre-existing request-side effect should be considered separately from this UI parity change.
