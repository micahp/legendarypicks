## 4. Play traces: what changes outcomes when it should not

- Debug mode: `simulate_pregame_batch.py --trace-dir` writes one trace per seed; `step_trace.py` steps through it; `--trace-outcome-probabilities` records the odds after each function.
- Trace build: local worktree `/root/lp-trace-pbv1-v2`, commit `ed231382` (PBV1 branch plus the slc-v2 trace code). Not for push.
- Traces and the analysis script: `/tmp/claude-0/-root/f1482f88-a0c5-4d01-ae23-395a1a954f9a/scratchpad/trace-was-nyg/` (`stage_effects.py`).
- **Finding: pass labels cut sacks in half** in V2 and PBV1. In the default `legacy` pass-label mode, the target, depth and direction labels weight the sack odds, and a sack has none of those labels. Expected sacks in one WAS-NYG game: base 4.25, after the labels 1.48. `--playcall-pass-label-mode two_stage` restores them (base 3.42, final 3.39). Interceptions are still cut to about 0.34 to 0.46 of base by several stacked weights.
- New or traded players: that game cannot test it. Only one player had no earlier snaps. A game with a trade or an IR return is needed.

## 5. Reproducibility finding

The same seed gives a different game for each commit, even when the code is the same. The share model writes the source commit into the reference fingerprint. The batch puts the fingerprint into the snapshot and reseals it (`pregame_snapshot.reseal`), and every random stream starts from that hash. Tested: same files with a new commit ID changed scores from 20-18, 13-10 to 12-27, 8-37. Same commit with changed files did not. So a same-seed comparison is valid only inside one commit.

## 7. V1 Complete

- New branch, to start from the end of V1-Pure. It is the base for the complete model family. Other branches (V2, PBV1) get compared to it after the realism work.
- Micah wants to talk about football realism and physics, not probabilities.
- **Football realism gates so far:**
  1. **Clock:** no sampled clock runoff. The clock comes from the rules and team decisions. This needs penalties (see open question).
  2. **QB in the pocket:** the QB decides over time. Examples from Micah: deciding, deciding, nobody open, deciding, sacked. Deciding, nobody open, run (by history and ability). Deciding, nobody open, throw it away.
  3. **The pass is a ball in flight:** landing point, height and speed give the flight path. Interception odds come from the throw, not a separate weight.
  4. **Pass completion** depends on the throw, the defender, the receiver running his route, and player ratings.
  5. **Play order:** personnel, formation and the call before the snap; then the snap, the live ball, the whistle and the next snap. No step reads a later one.
  6. **Timeouts are team decisions.** Done in V1-Pure.
- **Field model:** top-down 2D. Players are dots with position and speed. The ball has x and y plus a height number along its path. Results come from who reaches a point in time and whether the ball is catchable there. A tackle is a defender reaching the runner's dot. No animation and no collisions for now.
- **Ratings must come from data,** not a game. Candidate: nflverse Next Gen Stats (QB time to throw, air yards, completion above expected; receiver separation and cushion). Coverage for 2022-2026 is not checked yet.
- **Open question for Micah:** do penalties belong in V1 Complete? V1.7 already has a 16-foul penalty engine. If V1 Complete leaves penalties out, the "no clock runoff sampling" gate cannot pass. Recommended: take the V1.7 engine. How it handles the clock is not checked yet.
- Ball flight in 3D (height, speed, trajectory) was noted for later before the 2D decision; the 2D model keeps height as a number.
