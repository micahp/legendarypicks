## Correction 1 (material): the code does not do what the spec says

`SPEC.md` says the sack probability is restored "conditioned on the same down, distance and field-zone cells the sampler already uses". The implementation is a **flat `0.046` on every non-sack dropback**:

```python
if ('restore_sack_mass' in self.blocker_fixes and outcome_intent == 'dropback' and not scramble
        and fallback_by_key is None and key[1] != 'sack' and (outcome_intent, 'sack') in entry['by_key']
        and rng.random() < SACK_MASS_PI):
    key = (outcome_intent, 'sack')
```

The only conditioning is the guard `(outcome_intent, 'sack') in entry['by_key']`, which is a pool-availability check, not a rate condition. So 3rd-and-2 from the opponent's 40 and 3rd-and-12 from your own 10 get the same bump.

That matters because a flat bump inflates the sack rate where sacks are rare and known not to be the dominant outcome, and it changes the relationship between down and distance and the outcome mix. It will still move sacks to the target rate (rule 1 will pass), so the test will run — but it will be measuring "more sacks everywhere", not "sacks at the observed conditional rate", and the mechanism conclusion will not transfer to the real fix.

**Fix before freeze.** Either implement the cell-conditioned rate (per-cell target from the pool, `π_cell = (p_target,cell − p_engine,cell)/(1 − p_engine,cell)`, floored at 0), or amend `SPEC.md` to state plainly that A is a flat-rate stress test and that a pass only establishes that sack *volume* matters, not that the conditional model is right. Amending the spec before the baseline run is legitimate; letting the code and the spec disagree is not.

## Correction 2 (material): A is confounded with C under this implementation

The bump fires on any dropback whose drawn outcome is **not** a sack — including a 25-yard completion. It therefore converts good plays into sacks, not just incompletions into sacks. Consequences:

- The ablation will cut yards per play by much more than a real conditional sack model would, so a positive result partly reflects yardage reduction (which is ablation C) rather than sack-driven drive death.
- A null result would be uninterpretable, because the two effects push in the same direction on scoring.

**Fix before freeze, choose one:**

1. Restrict the substitution to outcomes a sack plausibly replaces — `pass_incomplete`, and optionally `interception` — so the arm does not steal completions. This is defensible: a sack is an unsuccessful dropback that is not thrown.
2. Keep the flat substitution, but add a gated diagnostic: "mean scrimmage yards per team-game moved by at most 15". If it moves more, the result is reported as confounded with C, not as a mechanism finding.

Option 1 is better and is barely more code.

## Correction 3: the bootstrap is at the wrong level

Rule 5 says "a 95% interval from a team-game bootstrap", and the power section derives SE ≈ 0.24pp from 5,200 team-games. That overstates precision twice over:

- 5,200 team-games are 2,600 **games**. The two team-games within a game are the same event viewed from both sides — and on scoring they move in opposite directions.
- Worse, they are 13 **matchups**, each sharing one snapshot and one input set. Seeds within a matchup are not independent draws of engine behaviour; they are 200 draws from one configuration.

The review's own cut tables used a **game-clustered** bootstrap for exactly this reason. Rule 5 must use a game-clustered bootstrap, and the power statement should be recomputed with the cluster count (2,600 games, 13 matchups), not the row count. As written, rule 5 will report intervals roughly half as wide as they should be and will call a 0.3pp move significant when it is not.

**Also consider a matchup-level leave-one-out**: report the 13 matchup-level changes and whether the sign is consistent. With a 13-cluster structure, a single matchup can drive the pooled result.

## Correction 4: rule 2's target band is tighter than the observation

Rule 2 requires the ≤3 share to "land in 2.5–3.0%". The observed value is 2.76%, but its own 95% interval from 544 team-games is **1.47% to 4.23%** (game-clustered; `scoring-tables/low-end-scoring.csv`). Requiring the simulated value to land inside a 0.5-point band around a point estimate whose interval spans 2.8 points is over-precise, and a near-miss would be recorded as a failure for a reason that is about the reference, not the engine.

**Restate rule 2 as directional:** the ≤3 share rises by at least 0.3pp and moves toward 2.76%, with the observed interval quoted beside it. Keep rules 3, 4 and 5 as written.

## Answers to the two questions in "Open items to confirm before freeze"

**Thresholds.** Confirmed as directional minimums: 0.3pp on ≤3, 1.0pp on ≤10. The 1.0pp figure closes a quarter of the 3.98pp gap and is deliberately conservative — keep it. Do not raise it; the point of A is to test a mechanism cheaply, not to close the gap in one step. Note that the ≤10 gap is driven mainly by the 0-point, 3-point, 7-point, 8-point and 10-point cells (0.26/0.91/0.91/0.10/3.40 simulated against 1.29/1.47/1.47/0.55/4.78 observed), so report the change at those five cells as a diagnostic, not just the ≤10 aggregate. If the ≤10 share rises but those cells do not move, the mechanism is not the one named.

**Turnover definition.** Use the review's **1.098 per team-game** from `SLC-2025-REALISM-RESULTS-2026-11-05/table_drive_half_totals.csv`, not the 1.19 you computed from raw PBP. Reason: the engine's `turnovers` box-score stat is compared against that 1.098 throughout the committed 2025 report, so it is the engine-comparable number. Your 2,578/2,174 definition counts interceptions plus fumbles lost from the play-by-play, which is a legitimate football definition but a different instrument — and mixing the two would make ablation B's baseline non-comparable with the rest of the review. Record both, gate on 1.098, report 1.19 as a cross-check.
