# SLC V1-Pure: minimal football-sequence control (2026-11-21)

**Status:** design and executable experiment launcher; **not yet simulated, calibrated or promoted**.

**Intra-play realism gate: FAIL / NOT IMPLEMENTED.** This is a whole-play statistical generator, not a causal snap-to-whistle simulator. The source-level proof of the missing intra-play phases and test coverage is in [SLC-V1-PURE-INTRAPLAY-ORDER-AUDIT-2026-11-21.md](SLC-V1-PURE-INTRAPLAY-ORDER-AUDIT-2026-11-21.md). A valid final score, a state reducer, and a clock reconciliation are insufficient to certify football-ordered execution.
This branch starts from frozen V1 `6895c2e3`; the original V1 code and profile remain unchanged.
V2-Pure implementation is owned separately and is **not** represented by these files.

## Goal

Separate the core football sequence from the accumulated historical-conditioning
stack. A valid control still draws a legal play, updates the game state and clock,
and reconciles player/team stats. It need not explain a football play with 14
independently generated decision labels and a succession of sparse row filters.

The planned execution is:

1. Game situation (quarter, clock, score, down, distance, spot, legal decisions).
2. **Called intent** (run, dropback, kick), using the frozen score-clock artifact.
3. Eligible participants and one basic, prior-season per-game usage draw.
4. Outcome family and historical source play from a supported situation pool.
5. Legal transition (downs, possession, clock, score), then accumulated stats.

This is **not** a named offensive playbook, a model of all 22 players, or Madden-level
execution. In a later playbook model, an actual play call occurs **before** the
pre-snap look; the call can then be adjusted by an audible or timeout.

## V1 versus V1-Pure ownership

| Mechanism | Historical V1 | V1-Pure first pass | Why |
| --- | --- | --- | --- |
| Score-clock playcall / legal kick choice | on | **on** | Core situational call |
| Historical event and yardage source pool | on | **on** | Minimal legal outcome generator |
| Roster eligibility and participants | on | **on** | Valid player identities and game statistics |
| Dirichlet player target/carry shares | on | **on** | Keep a distinct player-use component; calibrate separately |
| Exact-yardline historical row conditioning | on | **off** | Test separately; legality/field geometry remain enforced by rules |
| Team event outcome ratios | on | **off** | Not yet a distinct, validated opponent-strength model |
| Formation-conditioned outcome weighting/filter | on | **off** | No full called-play/formation consistency model yet |
| Defensive coverage prior/outcome filter | on | **off** | Incomplete observed defensive calls |
| QB-specific decision overrides | on | **off** | Leave historical event model as baseline; separate QB adaptation later |
| Player event/yardage multipliers | on | **off** | Do not stack outcome factors until validated |
| Target-role priors | on | **off** | Extra role-conditioning layer |
| A-N decision labels and lifts | on | **off** | Independently sampled attributes and event weighting |
| Sequential decision-row filter | on | **off** | Narrows row support after event selection |
| Playbook C/D/E label overrides | on | **off** | Not a named play or football playbook |
| Team score splits, team streak, league streak | on | **off** | Three overlapping run/pass propensity adjustments |
| Rules, possession, clock, scoring, validation | on | **on** | Non-negotiable invariants |
| Blocker fixes | on | **on, identical** | Keep legality constant across arms |

The Dirichlet player-usage draw is a **testable first-pass decision**, not a claim of full calibration. Exact-yardline historical-row filtering should be a separate ablation, not bundled into V1-Pure. V1-Pure
does not pretend all team or player abilities are identical in real football:
the correct next step is a separately specified, held-out-calibrated
offense/defense/player ability mechanism, not reinstating opaque team ratios.

## Run both arms on exactly one pushed snapshot and seed

Use `scripts/nfl_sequence/run_v1_pure_comparison.py` and pin
one accessible snapshot file for **both arms**. One existing candidate is
`docs/research/slc-was-nyg-tnf-2026-11-12/snapshot.json` on `slc-v2`
(internal snapshot sha256
`8e54a85057107437c1aedf26cce6d78a62483f8aa60795a4752c4a2efd552d2d`).
Copy/locate that exact existing file on the runner host. Its current
availability and file path in the V1 checkout are not assumed.

Example after locating the pinned files:

```bash
python3 scripts/nfl_sequence/run_v1_pure_comparison.py \
  --snapshot-file /path/to/frozen/snapshot.json \
  --db /path/to/read-only/research.db \
  --playcall-artifact docs/research/SLC-PLAYCALL-ARTIFACT-v1.json \
  --playcall-streak-file /path/to/frozen/wl-streaks-through-week9.json \
  --seed-start 300001 --games 1 \
  --out-dir /path/to/results/v1-pure-300001 \
  --execute
```

Remove `--execute` to record a dry run first. Same snapshot file, artifact,
DB and seed range; different explicit optional mechanisms. The launcher writes
a manifest, each arm's batch output, seed/box-score ledgers and logs.
The database is not fully SHA-256 checked by this lightweight launcher and
must be pinned separately before treating the result as fully reproducible.

For a **true step-by-step full-game trace**, the existing
`run_slc_game.py` exposes `event_trace` and `result` on a single seed:

```bash
python3 scripts/nfl_sequence/run_slc_game.py \
  --snapshot-file /path/to/frozen/snapshot.json --db /path/to/read-only/research.db \
  --artifact docs/research/SLC-PLAYCALL-ARTIFACT-v1.json \
  --slc-profile custom --dirichlet-shares \
  --seed 300001 --out /path/to/results/v1-pure-trace.json
```

To inspect the unchanged original V1, use the same inputs with
`--slc-profile v1_full_stack --streak-file /path/to/frozen/wl-streaks-through-week9.json`
instead of the custom profile and its two flags. Keep rules/blocker-fix flags
matched across both traces.

## Acceptance gates

1. Every arm completes legal games and reconciles clocks, team and player stats.
2. Compare P(run/dropback), event frequencies, source-row effective support,
   3rd/4th downs, drives, possessions, and timed play volume.
3. Compare team-point **means, medians, P10/P90 and P5/P95 bands**, totals,
   sacks, turnovers, touchdowns, FG and low/high score tails.
4. Use chronological held-out games; no single score or arbitrary
   sample-seed result determines inclusion of a mechanism.
5. A separate V2 agent uses the **same snapshot bytes and seed** to produce
   an actual V2 per-play trace. A same seed ID alone does not guarantee
   common random numbers between V1 and V2.
