# SLC layer calibration audit, 2026-10-29

## Verdict

The SLC layers are wired to the engine, but the stack is **not calibrated as a whole**. The existing evidence is uneven: player target and carry shares improve held-out joint log scores for a restricted returning-player cohort; receiver-conditioned outcome scores improve; QB target-role and completion-result scores regress; several other layers have only small one-matchup paired runs. The simulator also produces too many scrimmage plays and underconverts red-zone trips. Keep research switches off by default and do not use a Week 8 10K batch as calibration evidence.

The current smoke establishes that the batch engine executes a complete game with all currently available SLC switches enabled. One game verifies execution and manifest wiring only. It does not validate any probability distribution.

## System-level calibration blockers

The corrected 2024 default red-zone cohort has essentially the same trip rate as actual: 3.294 versus 3.311 trips per team-game, difference -0.018 with 95% game-cluster interval [-0.172, +0.139]. Default conversion is low (0.495 versus 0.583 touchdowns per trip), and default red-zone run/pass volume is high (10.350 versus 9.669 per team-game). The matched exact-yardline arm changes those to 0.537 touchdowns per trip and 9.578 plays per team-game, moving both toward actual. Pass and run yardage remain low in the default replay (0.52 and 0.69 yards per matched play versus 3.78 and 2.80 actual); the exact-yardline comparison must be checked for yardage and drive-terminal effects before calling the mechanism calibrated.

The 2025 pace diagnostic shows about 10% too many scrimmage plays before the decision layer. Excess plays distort player opportunity totals and scoring rates, so opportunity-share calibration alone cannot make full player projections credible.

## Calibration protocol required before calling a layer calibrated

1. Freeze layer-specific estimands, cohort, source cutoff, comparison arms and acceptance metric before fitting. Use a training period, a separate tuning period, and an untouched chronological holdout. The existing source data do not provide row-level publication timestamps, so retrospective replays remain exploratory until availability is independently established.
2. Compare a layer off/on against both the pooled baseline and the existing team-conditioned baseline with identical eligible events, source cutoff and seeds. Keep each optional layer independently switchable; do not bundle decision filters or playbook inputs into a player-model comparison.
3. For probabilities, report log loss and Brier score, reliability by predicted-probability bins, calibration intercept/slope, and support by state. For counts and continuous outcomes, report mean, variance, quantiles, zero rates and proper distribution scores. Cluster uncertainty by NFL game; keep Monte Carlo seed uncertainty separate.
4. For full games, also score points, win/tie probabilities, plays, drives, possessions, clock use, red-zone entry and conversion. Reconcile emitted participants to the frozen roster and verify assignment occurs before the outcome draw.
5. Store model version, exact training cutoff, input and source hashes, code hashes, seed ledger and valid-game coverage in every result. A layer passes only on its own held-out criteria and does not inherit a pass from another layer or from a full-stack smoke.
