## 2. Two scoreboard defects, both diagnosed rather than guessed (v0.8.9)

- **Back from a game detail lost the day and the league filter.** `pages/scores.tsx` READ
  `?date=` and `?league=` into state and never wrote either back; there is no `router.push`
  anywhere in the file. So back returned to a bare `/scores`, which resets to today. Fixed
  with a shallow query write on every state change, defaults kept out of the URL, `?live=1`
  preserved.
- **A game detail tab that failed once stayed empty forever.** Two defects, both rendering
  an EMPTY tab rather than raising, which is why it read as missing data. The load latch was
  keyed on the tab name alone and Next.js reuses the page component across
  `/game/[league]/[gameId]` navigations, so moving between games kept the previous game's
  latch. It was also set BEFORE the await resolved with nothing catching a rejection.
- **The backend was never at fault**, measured against prod for game `401816603`: boxscore
  2 teams and 4 player groups, playbyplay 9 periods, gameinfo venue and attendance.

## 4. Tennis rankings: the seed is already published and we discard it

- **`competitors[].curatedRank.current`** rides on the tennis scoreboard payload we already
  fetch. Measured: Winston-Salem men's singles 16 of 118 competitors, values exactly 1..16,
  so it is the tournament SEED, not a world ranking. `espn_client/scoreboard.py:270` builds
  `{abbrev, name, score}` and drops it, along with the ESPN athlete id.
- **World rankings exist and verify against both publishers.**
  `sports.core.api.espn.com/v2/sports/tennis/leagues/{atp,wta}/rankings`. The athlete id is
  in the `$ref` URL, so it joins to the scoreboard competitor with **no name matching and no
  per-athlete fan-out**. Verified rank for rank: **WTA 100 of 100 points-exact against
  `api.wtatennis.com`; ATP 50 of 50 against tennisexplorer.com.**
- **Three traps measured**: 150 is a hard cap (`&limit=1000` still returns 150); ESPN
  publishes ONE week, not a series (33 and 35 both 404), so `captured_at` must be in the
  primary key or we get no history; and do not key the table on player name the way
  `ufc_rankings` does.
- **Dead ends, so nobody spends the requests again**: every `atptour.com` host including
  `app.atptour.com/api/v2/gateway` is Cloudflare-403 from this box, `api.atptour.com` does
  not resolve, `api.sofascore.com` is walled, `live-tennis.eu` is 403, and **Jeff Sackmann's
  `tennis_atp`/`tennis_wta` repos no longer exist** (that account now holds one repo).

## 6. Leagues Cup props: RotoWire has them and we discard them

> **SUPERSEDED 2026-08-25 (later pass). The headline is false.** This section counted

> clubs appear in the relay every week because Liga MX plays every week.

> The live payload confirms it for that endpoint: `Toluca` 0 occurrences, `Columbus` 0,
> `América` 0, `Cup` 0. We cannot be discarding strings that never arrive, so the

## 8. Timers: 20 to 14, and the duplication was never per league

Only 4 of 20 timers were league-scoped. The rest already handle every league in one run;
`ingest_scoreboards.py` covers ten leagues per invocation. **The duplication axis was
dev/prod**, six times over.

```
nfl-adp{,-prod} + nfl-transactions{,-prod}   4 -> 1  legendarypicks-nfl-daily   04:10
news{,-prod}                                 2 -> 1                             03:35
news-x{,-prod}                               2 -> 1                             0/2:15
scoreboards{,-prod}                          2 -> 1                             *:00/10
scoreboards-live{,-prod}                     2 -> 2  LEFT SPLIT, see below
```

**Sequential beats staggered.** The dev/prod offsets existed to keep both off ESPN in the
same minute, and §11 of 08-24 proved an offset only MOVES a collision. One job running the
environments in order guarantees they never overlap.

**Measured before touching the scoreboard pair**, because consolidating could have fought
the staggering added that same day:

```
ingest_scoreboards: 755 runs, requests per run median 2, max 118
all-proc per minute: median 8, p90 38, max 122
403 onset (measured 08-19): ~63 in the prior 60s
minutes at or above 60: 20 of 380
```

At a median of 2 requests per run, both environments together is ~4 against a threshold of
63. Safe.

**`scoreboards-live` deliberately left as a pair.** It fires every 60 seconds with
`TimeoutStartSec=120`. Consolidating doubles per-invocation work on a job with no headroom,
trading a race between two units for a queue inside one, on the sport with live scores four
days before NCAAF opens.

**Error handling reuses `news-lib.sh` rather than copying it**, which is what that file's own
comment asks for. `run_step` gained an optional `LP_STEP_LABEL` prefix so a job running one
script against two databases can tell its failures apart; unset, every existing caller is
unchanged, proved both ways. The two levels it already implements are exactly what was
wanted: a step logs `OK`/`TIMEOUT`/`WARN` and always returns 0 so later steps still run, and
`finish()` fails the JOB naming what broke.

Every unit was tested against the command **systemd actually parsed** (`systemctl show -p
ExecStart`), not against my reading of the file, with both a success path and a DEV-fails
path proving PROD still runs and the unit still goes red. All 41 unit files backed up to
`ops/systemd-backup-20260825-010806` first.
