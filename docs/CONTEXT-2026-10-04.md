## ESPN: why it refused, and the fix

`backend/data/http-spend.jsonl`, non-cached `site.web.api.espn.com`:

| period | requests/day | refused |
|---|---|---|
| late August | 2,500-7,000 | 3-5% |
| mid September | 15,000-19,000 | ~10% |
| 10-02, 10-03 | 23,700 / 25,900 | 19-21% |

`settle_props.py` was ~70% of it: every 30-minute run re-fetched an ESPN box score for every game
with any unsettled prop, no age bound (~900 games a run in dev, ~830 in prod, most 8+ days old).
146 of 149 refused minutes on 10-04 morning had it running; its refusals spilled onto the scoreboard
ingest and the site.

**Settlement now reads the database only** (Codex, spec `logs/TASK-settlement-db-only.md`):
- `30db548` `game_summaries` table + `ingest_game_summaries.py`: one ESPN summary per finished game,
  stored once. UFC skipped (ESPN 404s its summaries; `3b8c559`, placeholder fix `c9b2a0a`).
- `ac45df7` `settle_game.py` reads stored scoreboard rows for finality and `stored_summary` for box
  scores. Zero network calls.
- `e03e6f1` 72 h window: props on games past 72 h get one `settlement_attempts` row with
  `terminal='manual'` and are never retried (first run flagged ~69,903 props in a dev copy).
- Proof: on a dev copy, NFL game 8834's 2,370 settled props were deleted and re-settled by the new
  code **identically, 2,370 of 2,370, with zero ESPN calls**. Settlement back on `8456c9d`.
