# Context Summary — Mock-Draft Incident and Public-Response Boundaries — August 21, 2026

## Read first

This is an incident handoff. It records live production changes made under
direct user authorization after `/mock-draft` showed **Load Failed** on a real
mobile client. Do not reduce this to “the endpoint returned 200”: nginx logged
the real failure while its access log still recorded a 200.

## What failed

Public request path:

```text
browser -> host nginx :443 -> 127.0.0.1:8100 -> Docker backend :8000
```

The application frontend and backend are Docker containers, but the public TLS
edge is a shared **host nginx** process, not a container. Nginx workers run as
`www-data`.

The mock-draft pool originally returned 4,550 rows / 2,914,287 bytes. A slow
client made nginx buffer that large upstream response in its default host temp
directory, `/var/lib/nginx/proxy`. Those numbered directories were legacy-owned
by `nobody:nogroup`, so the nginx workers could not create a temporary file.

Exact error shape from `/var/log/nginx/error.log`:

```text
open() "/var/lib/nginx/proxy/<n>/44/<file>" failed (13: Permission denied)
while reading upstream, request: GET /api/nfl/mock-draft/pool?season=2026
```

It occurred for the affected mobile client at 11:16, 11:21, and 11:26 CDT.
Treat access-log 200s as insufficient when a proxy error accompanies them.

## Security finding

This was an **availability failure**, not evidence of a public data leak:

- There is no configured persistent `proxy_cache` for LegendaryPicks.
- `/var/lib/nginx/proxy` is not web-served.
- The audit found zero retained proxy files after requests completed.
- Docker backend/frontend ports remain bound only to loopback (`127.0.0.1:8100`
  and `127.0.0.1:3100`); no port, CORS policy, auth rule, mount, or public
  backend exposure was added.

Historically, nginx could have created transient local temp files during large
responses. The mock-draft route no longer does so. Do not call this an
independent security boundary for sensitive responses: keep public payloads
minimal, and audit any authenticated large response before enabling a similar
streaming rule.

## Production changes made

### 1. Bounded the actual draft pool

Managed `dev` commit `745de85` (`fix(mock-draft): publish only selectable
players`) is deployed in the Docker stack. It changes
`GET /api/nfl/mock-draft/pool?season=2026` to return only the supported fantasy
positions with a publisher-backed ADP.

This did **not** reduce selectable players:

| State | Rows sent | Selectable by current client engine |
|---|---:|---:|
| Before | 4,550 | 1,027 |
| After | 1,027 | 1,027 |

The removed 3,523 rows had no ADP and were already discarded by
`pages/mock-draft.tsx` before a draft starts. The live response dropped from
2,914,287 to 809,643 bytes, with zero null ADPs.

### 2. Disabled host buffering only for the pool route

`/etc/nginx/sites-available/legendarypicks.xyz.conf` now contains an exact
`location = /api/nfl/mock-draft/pool` stanza that retains the existing
loopback backend and forwarding headers, but sets `proxy_buffering off`.
`nginx -t` passed before `systemctl reload nginx`.

The staged equivalent is checked in at `docs/legendarypicks.xyz.conf`; its
generic API rule was also corrected to preserve the `/api/` prefix like the
live vhost. Keep the two synchronized. This is deliberately not a broad
`/api/` buffering change.

### 3. Repaired existing nginx temp-directory ownership

`/var/lib/nginx/proxy` and descendants are now `www-data:www-data` mode 755,
which matches the nginx worker account. This fixes the pre-existing bad
ownership for other host-proxied paths. It is a host-level operational change,
not a database or container change.

## Prevent this class of failure

1. **Response-budget gate.** Every public list/board endpoint must record real
   returned rows and compressed/uncompressed bytes through the public proxy.
   A virtualized browser table does not bound JSON serialization, transfer,
   browser parsing, or nginx buffering.
2. **Eligibility before serialization.** Query/filter exactly the product’s
   selectable/renderable population in SQL. Do not send a broad source universe
   and rely on the browser to discard it.
3. **Proxy-error monitoring.** Alert on nginx `crit`/`error` lines tied to
   `legendarypicks.xyz`, especially `Permission denied while reading upstream`,
   upstream resets, and 5xx responses. Access-log status alone is not an
   availability monitor.
4. **Host-path ownership check.** Before deploying any route that can buffer or
   upload, verify the worker account can create and remove a file in its exact
   temp path. The relevant nginx process here is `www-data`.
5. **Route-scoped proxy policy.** Use `proxy_buffering off` only for a measured,
   safe response path. Do not turn it off globally: buffering protects upstream
   services from slow readers. For authenticated/download endpoints, perform a
   separate security and capacity review.
6. **One deployment command at a time.** An interrupted compose build can keep
   running. Before retrying, inspect `ps` and Docker build state; stop only a
   confirmed duplicate and verify it exited. Never run parallel production
   builds on this constrained host.
7. **Public browser gate.** After every production API/proxy change, load the
   actual public URL in a clean browser, inspect failed responses and console
   errors, then inspect nginx error logs for the same request window.

## Next authorized work

The immediate incident is repaired. Do not broaden this into an all-Docker
ingress migration without a dedicated plan: host nginx owns shared ports 80/443
and certificate handling for multiple sites. A LegendaryPicks-only nginx
container would not eliminate host buffering unless the outer host proxy also
has a route-specific policy.
