## DO THIS FIRST

Nothing blocks a release. The open items are additive:

1. **The crosswalk needs two passes on a cold database.** `club_crosswalk.learn` reads
   existing bindings, and bindings need the crosswalk, so a brand-new league converges on
   the second daily run. Both databases are converged now. Folding a second learn/fill pass

2. **`unresolved_players` should be re-measured.** 873,559 attempts were the reason for all

   dropped; that name now resolves. Nobody has re-counted the queue since the bindings
   landed.
3. **`refresh_mlb_player_teams.py` is in no registry entry and no systemd unit.** The league
   that first solved the stale-club problem only gets the fix when a human runs it.

## The one thing to carry forward

**Identity is a question about ids, not about names, and the shape of a field decides
whether you may copy it.** Every strand of today turned on that. A club is a definition and
copying it from the publisher is right. A name is a rendering and copying it makes the data
worse. A club is identified by its squad, not by what anyone calls it. And a competition's
roster row is the same person as a league's when the publisher's id says so, whatever either
one is spelled.

## 1. v0.9.3 shipped

Codex had produced the candidate overnight (`167060c`) and hit a rate limit at 01:16. It
rebuilt the previous session's WIP on a better boundary: **roster ingest owns identity
creation; the request path only reads.** `_resolve_player_for_ingest` had been inserting a
`players` row inside `/api/props/ingest` while its own docstring said it never inserts.

The tag was blocked on one thing, and the gate was right: `published_roster_name` existed on
dev and not on prod, so `scripts/release.sh` stopped at the prod-vs-dev preflight.

**A mistake worth recording.** `migrate_published_roster_name.py` called
`published_roster.ensure()`, which also adds `team_code` and `player_id`, so it did more
than its docstring claimed and pushed prod AHEAD of dev. Worse, it returned early once the
table existed, so it could not level dev back. The dry run caught it in the opposite
direction. Fixed in `b798078`: every check runs every time.

Deployed with `docker compose up -d --build backend` after sourcing `/root/.hermes/.env`.
All six API keys survived; the documented esports-keys gotcha did not bite.

## 2. A transfer is not a failure

`publish_identities` refused every unbound namesake at a different club as a
`team_conflict`. That compared `players.team`, a last-known value with **no timestamp**,
against the publisher's CURRENT squad, and called the difference evidence of two humans. It
also exited 2 on every such row, so the daily job was red on every run for rows that were
never defects.

Ask the game logs, which are dated:

| evidence | verdict | action |
|---|---|---|
| publisher's club appears in their logs | `stale_team` | bind; our stored team is the outlier |
| stored club appears in their logs | `transfers` | bind; the publisher has the newer fact |
| neither appears | `unverified_team` | refuse, still exits 2 |

All four prod refusals were real: Jacob Jackson (4 logs at DAL), Sam Vines (22 COL + 3 HOU),
Wilson Eisner (**4 logs at SD**, so `SJ` was simply wrong). One of Eisner's own logs is
`SD away at SJ`, which rules out the SJ/SD near-miss with independent evidence.

## 3. The roster is the crosswalk

`published_roster.team_code` came from `link_prop_games._norm_team`, a static map covering
MLS alone. On prod: lcup 1035/1035 rows with no code and 100% unbound, ligamx 483/483 with
no code. **1,100 identities that could never bind, and nothing raised.**

`league_clubs` already held both halves. Joining them **on the name bridged 2 of 11** Liga MX
clubs, because ESPN files nicknames (`Rayados`, `Panzas Verdes`, `La Franja`). **The squad
bridged 18 of 18**: `Chivas -> GDL 19/19`, `Pumas -> UNAM 27/27`, `Tigres -> UANL 22/23`.

Learned cross-league, so Leagues Cup inherited 35 of 36 with zero bindings of its own.
Uniqueness is judged PER LEAGUE: `ATL` is Atlanta United in MLS and Atlante in Liga MX and
both are right; only the shared competition loses it. `backend/club_crosswalk.py`.

**Individual sports never teach it.** `ingest_ufc_fight_stats/roster.py` reuses
`players.team` to carry the OPPONENT: 242 of 248 UFC values are another fighter's name, 232
reciprocal. ATP and WTA store no team at all, which is correct.

## 4. The fix that armed a worse bug

Rehearsed on a clone, the crosswalk plus the existing code **inserted 1,004 Leagues Cup
players of whom 997 (99%) already existed** in MLS or Liga MX. Leagues Cup owns nobody; its
people live in the two home leagues. Before the crosswalk, every lcup row failed on
`missing_team` and never reached the creation path, so **the missing join key was the only
thing preventing 997 shadow rows.**

`NO_MINT_LEAGUES` shipped in the same commit as the unblocker, never after.

Then the binding, which was exact all along: FotMob does not renumber a player because he
entered a second competition, so all 1,035 lcup rows share a FotMob id with an mls or ligamx
row. A borrowed identity is bound and nothing else; their club and active flag belong to
their home league. `lookup_player` joined `p.league = r.league` and had to be relaxed for
exactly these competitions.

**The first version was not idempotent**: it decided borrowing per RUN, so pass one bound
1,035 and pass two refused all 1,035 as conflicts, because the owner then arrived via
`source_owners` and a league-scoped existence check cannot see a person in another league.
Borrowing is a property of the competition.

## 5. Copy a definition, not a rendering

`refresh_soccer_player_teams.py` copies the club from the publisher, same argument as
`refresh_mlb_player_teams.py`: a team is a DEFINITION. 27 prod clubs refreshed, 0 contested.

Extending that to names would have been wrong. Of 1,514 bound players, 14 hold a name no
publisher spelling folds to, and **13 are our rendering being better**: `JT Marcinkowski`
against `James Marcinkowski`, `Evander` against `Evander Da Silva Ferreira`, `Kim Kee-Hee`
against `Kee-Hee Kim`. So `repair_reviewed_player_names.py` is a reviewed list with
citations keyed on the publisher's id, not a refresh.

Its one entry is the best story of the day. `players.name` said **Alisa Randell**;
mlssoccer.com displays **Darius Randell** and files him at `/players/alisa-randell/`, while
`/players/darius-randell/` is a 404. **MLS's own bad slug is also what bound him**, through
the alternate-spelling table added to retire the manual aliases: `dariusrandell` never
matched our row and `alisarandell`, harvested from the publisher's URL, did.

## 6. Vocabulary repairs

**MLB carried both spellings of two clubs.** `AZ` 1832 rows and `CWS` 1885 against `ARI` 214
and `CHW` 246 from 2026-07-26, the day the conversion started working with no backfill.
3,741 prod values and 3,026 dev.

**The NBA All-Star game was shaped like a regular-season game.** 24 rows on 2026-02-15 with
`game_type` NULL. The team names STARS/STRIPES/WORLD are CORRECT and were not renamed; they
are marked `ALLSTAR` from `game_types`. Dev already had this; prod never got it.

**NHL moved onto the league's own tricodes.** The map said LAK/SJS/TBL/UTA and the data said
LA/SJ/TB/UTAH on 129 players and 6,450 log rows. Verified against
`api.nhle.com/stats/rest/en/team`: the map was right. **13,864 values across 7 tables, every
statement league-scoped**, because LA/SJ/TB are live codes elsewhere and an unscoped rename
would have hit 641 nfl_snap_counts rows and 1,202 non-NHL players. Rehearsal confirmed those
counts byte-identical before and after.
