## 1. Finished games rendered as if they'd never happened

Reported by Micah on MLS specifically ("shows live during the game, but after it'll
show like it never happened"). Confirmed and generalized: **any** league captured
into `scoreboard_snapshots` (mls, lcup, ligamx, ncaaf, nfl, atp, wta) but whose
`team_game_results` row hadn't landed yet — routine for a game that just went final —
rendered `final_score: null`.

**Root cause** (`backend/routers/games/game_detail.py`): the handler read game state
from the snapshot and threw the score away alongside it (`snap_state, _ = ...`),
betting `_final_score_from_db` (which reads `scoring_plays`/`team_game_results`)
would supply it later. That source lags. Once the snapshot's team **names**
populated `context`, the only other fallback that fetches a score became
unreachable — its guard is `not team_stats and not context`, and `team_stats` is
always empty for every non-NBA/NHL league. World Cup coincidentally never hit this:
it isn't in `scoreboard_snapshots` at all, so it always fell through to the
ESPN-live fallback that sets score and context together — which is why one soccer
league "worked" and the others didn't, and why the first read of this bug (comparing
only against WC) was wrong.

**Fix:** take the snapshot's score at the point state is read, when state is `post`.
`_final_score_from_db` still overwrites it later when the source of record has
caught up — precedence unchanged. Verified live on MLS 761758/761769. Two new tests
in `backend/test_game_detail_db_first.py`.

## 2. Season Records silently broken almost everywhere

Same sweep, different symptom: GameInfo's "Season Records" card rendered its heading
over an empty grid for MLB and NFL (checked both; likely every non-soccer-abbrev
league). Cause: `context.home_team`/`away_team` holds a full display name
("Washington Nationals") for leagues whose context comes from the snapshot's
team-NAME fallback, but `espn.team_strength_map(lg)` is abbrev-keyed ("WSH") — a
silent-miss key mismatch, not a data gap. Real strength rows sat unused for both
teams on both leagues checked.

**Fix:** `_strength_for()` in `backend/_core.py` — abbrev lookup first, falls back to
a scan-by-display-name. Also made the GameInfo card hide entirely rather than render
empty when genuinely no data exists (ATP/WTA pre-season is the honest case this still
has to cover). New test: `backend/test_strength_for_name_or_abbrev.py`.

## 10. A live match spanning local midnight vanished from "today"

Venus Williams vs. Sofia Kenin (US Open, live) was correctly stored and served —
`state: 'in'` — the bug was entirely frontend. `services/sports.ts`'s
`getGamesByLocalDate` buckets games by the **viewer's local calendar day**, and her
match started `2026-08-31T04:10Z` — 2026-08-30 23:10 in every US timezone except
Eastern. Technically correct local-day arithmetic, wrong answer for "is this on
today's board": a match still being played right now is relevant today regardless of
which side of local midnight its start instant falls on.

**Fix:** a game with `status === 'LIVE'` is now always kept when the caller is
viewing their own current day (compares against a freshly-computed `today`, not the
requested date itself) — explicitly does NOT apply when browsing a past/future date,
verified separately so a live game can't leak onto a date the viewer isn't actually
looking at "now" for. Verified across Chicago/LA/NY/UTC timezones (only
Central/Pacific-style zones were affected). 2 new tests in
`services/sports.local-date.test.ts`.

## 11. Tennis players are now searchable end to end (`605203a`)

The global player search excluded ATP/WTA even though the canonical tennis spine
was present in both DEV and production databases. There were three separate holes:

1. `offered_leagues()` only treated UFC/World Cup as non-team-stat shape
   exceptions. ATP/WTA can never have `team_stats_coverage`, so the search gate
   filtered them out before ranking or prop evidence mattered.
2. Search considered only game logs, props, and season stats. Tennis currently has
   published world-ranking snapshots rather than game logs/season-stat rows, so a
   ranked player without a current prop was classified as an empty identity.
3. Tennis players correctly have `team=NULL`, but the dropdown rendered the team
   separator unconditionally, producing a dangling ` · ATP`/` · WTA` label.

**Fix:** ATP and WTA are explicit non-team-sport offerings; `/api/players/search`
uses canonical `players.id` plus persisted `tennis_ranking_snapshots` or existing
prop evidence, reports `coverage.rankings`, and tolerates an older database where
the ranking table is absent. `scoreboard_store` now creates a player-ID index for
the ranking lookup. The dropdown renders teamless results as just `ATP` or `WTA`.

Search results now lead somewhere useful instead of a profile that says no data:
`/api/player/{id}` reads the player's latest stored ranking, includes it in coverage
and readiness, and the player page renders a restrained **World Ranking** card with
tour, rank, points, source, and snapshot date.

**Measured population and verification:**

- DEV and production each held 155 ATP + 154 WTA canonical identities; all 309 had
  ESPN IDs.
- The latest published ranking population was exactly 150 ATP + 150 WTA. Props
  independently covered 59 ATP + 47 WTA identities.
- Every latest-ranked player was searched by exact published name against the
  read-only DEV database: **300/300 returned its canonical player ID, zero misses**.
- The running managed DEV API returned Jannik Sinner (`id=59339`, ATP, rank 1) and
  Coco Gauff (`id=59492`, WTA, rank 4); Sinner's profile returned
  `data_status=ready` with ranking coverage.
- Before landing: 42 focused backend tests and 2 focused frontend tests passed.
  After landing in managed DEV: **44 backend tests** (including the real-DB offering
  checks) and both frontend suites passed; Python compilation and diff checks passed.
