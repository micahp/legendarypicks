### Architectural Goal (≈100–200 words)
We are evolving Legendary Picks into a cost-efficient, resilient sports data platform that bridges on-chain assets (NBA Top Shot) with game experiences (scores, contests, predictions). The primary objective is to centralize all provider selection and normalization behind a single API contract while ensuring the UI remains resilient to rate limits, inconsistent schemas, and partial on-chain metadata availability. This matters to users who expect reliable scores and a smooth moments gallery (even before connecting a wallet), and to the business which must minimize operational costs by leveraging free or low-cost providers without sacrificing stability. On-chain, we align with Cadence 1.0’s capability model and public views, avoiding privileged access and improving security. Off-chain, we add a provider switch with retry and caching so we can quickly pivot between sources (FastAPI using `nba_api` vs. SportsData) with no UI changes. This architecture unlocks faster feature additions (roster stats, contests) without re-architecting core flows.

### Deep-Dive Highlights (≈300–500 words)
- Centralized Provider Switching (Next API)
  - The route `pages/api/nba/games.ts` now owns provider selection. It accepts `?provider=sportsdata|fastapi|nba_api` (or uses `NBA_PROVIDER`). When `sportsdata`, it calls SportsData.io’s GamesByDate with exponential backoff (429/5xx) and a 60s in-memory cache; when `fastapi|nba_api`, it proxies to the Python backend. Status strings are normalized to `SCHEDULED`, `LIVE`, or `FINAL`.
  - Key logic: provider switch, retry/cache, and mapping into our internal `Game` shape.

- Defaults & Scoring (NBA MVP tweaks)
  - Default provider is now `nba_api` (via FastAPI proxy) to minimize cost by default; can still switch
    to `sportsdata` when the paid key is present.
  - Fantasy scoring weights set to: Points=1.0, Rebounds=1.2, Assists=1.5, Steals=3.0, Blocks=3.0,
    Turnovers=−1.0.

- FastAPI `nba_api` by-date Endpoint
  - `backend/nba_service.py` adds `GET /api/games/by-date?date=YYYY-MM-DD`. It converts to MM/DD/YYYY for `scoreboardv2.ScoreboardV2`, then joins `GameHeader` and `LineScore` to produce `{ gameId, homeTeam, awayTeam, startTime, status }`. This gives a free provider path with acceptable latency.

- Cadence 1.0 & Top Shot Metadata Resolution
  - Previous scripts failed due to deprecated syntax and incorrect types. Now `services/nbaTopShot.ts` borrows NFTs from the public collection capability and uses `ViewResolver` to obtain `TopShot.TopShotMomentMetadataView`. Everything is read-only and aligned with public interfaces, avoiding `getAuthAccount` or private storage access.
  - Env-driven addresses (`NEXT_PUBLIC_TOPSHOT_ADDRESS`, `NEXT_PUBLIC_METADATAVIEWS_ADDRESS`, `NEXT_PUBLIC_VIEWRESOLVER_ADDRESS`) ensure correctness on mainnet.

- UI Resilience & Observability
  - `components/MomentGallery.tsx` enables manual address input when no wallet is connected, making it easy to test live addresses. It filters out null metadata items, guards all metadata reads with optional chaining and defaults, and displays counters for “Total Moments Found” (IDs) and “Metadata Resolved” (mapped items). This prevents runtime crashes and aids triage when views are unavailable for certain moments.
  - Added `components/ContestLeaderboard.tsx` and rendered in `ContestEntry` as a stub (leaderboard only; no
    payouts yet). Will populate as scoring hooks are wired.

- Security & Cost Implications
  - Keys are protected server-side; the UI never talks directly to paid providers. The cache reduces burst costs and improves responsiveness. Cadence changes harden the app by ensuring only public capabilities are used.

### Decision Log
- **Decision**: Centralize provider switching behind Next API. **Rationale**: Protect keys, normalize schemas, and allow quick pivots. **Alternatives**: Client-side switching (exposed keys), single provider (rate/cost risk).
- **Decision**: Add FastAPI `nba_api` path for free data. **Rationale**: Reduce costs, mitigate rate limits. **Alternatives**: SportsData-only; custom scraper (maintenance-heavy).
- **Decision**: Migrate to Cadence 1.0 and use `ViewResolver` for metadata. **Rationale**: Fix deprecations, avoid unauthorized storage reads, increase compatibility. **Alternatives**: Entitlement traversal (deferred), off-chain-only metadata (fallback, not primary).

### Risks & Mitigations
- Rate limits and outages (technical): Backoff+cache for SportsData; quick flip to `nba_api` provider. Add circuit-breaker if instability persists.
- Partial on-chain metadata (technical): Some Moments lack the view; UI now guards and shows counts. Add off-chain fallback to improve coverage.
- Mapping drift across providers (technical): Normalize and unit test provider mappers; log diffs on status/field changes.
- Maintenance overhead (schedule): Two providers to maintain; mitigate by centralizing normalization and adding test fixtures.
